# URDF_arm 在 MuJoCo 中打开

把 `../URDF_arm` 里的六轴机械臂（base_link + Link1~Link6，Joint1~Joint6）转成 MuJoCo
模型，并提供一个查看窗口。

```
arm_mujoco/
├── build_model.py      # 从 ../URDF_arm 生成 URDF_arm.xml 和 assets/
├── view_arm.py         # 在 MuJoCo 中打开模型
├── URDF_arm.xml        # 生成物：MJCF 模型
└── assets/             # 生成物，可随时删掉重跑
    ├── URDF_arm.urdf   # 中间产物，只给 MuJoCo 的 URDF 解析器当输入
    └── meshes/*.STL, Link3.obj
```

## 环境

MuJoCo 3.9.0 装在 conda 的 base 环境里（`legged_gym` 环境没有 mujoco）：

```bash
/home/wck/miniconda3/bin/python view_arm.py
```

## 用法

```bash
python build_model.py          # 生成模型（改过源 URDF 后重跑即可）
python view_arm.py             # 开窗口，六个关节按正弦摆动
```

常用参数：

| 参数 | 说明 |
| --- | --- |
| `--static_pose` | 停在零位，只看模型或调姿态 |
| `--camera front` | 用模型里预置的固定相机，默认是自由视角 |
| `--amplitude_scale 0.35` | 摆动幅度占关节行程的比例 |
| `--frequency 0.25` | 摆动频率（Hz） |
| `--no_skybox` | 不加载天空盒 |
| `--headless --steps 2000` | 不开窗口只跑物理，用来验证模型 |

窗口用 MuJoCo 自带的被动查看器：鼠标左键拖动 = 转视角，滚轮 = 缩放，右键拖动 = 平移，
空格 = 暂停，ESC = 退出。左侧面板可以拖关节滑块、看接触点、切相机，右侧有 Control 面板
可以直接改控制量。

`--headless` 下会打印连杆质量、关节限位和每四分之一行程的关节角。

## 拖拽目标 + IK 控制（ik_control.py）

```bash
python ik_control.py
```

场景里有个红色 mocap 目标球，**Ctrl + 左键拖动**移动它（Ctrl + 右键拖动是旋转姿态），
手臂用阻尼最小二乘 IK 跟过去。末端上的**绿色小球**是实际末端位置，红绿两球的距离就是
当前误差。

| 按键 | 作用 |
| --- | --- |
| 方向键 | 目标在 x / y 方向平移 1 cm |
| Page Up / Down | 目标在 z 方向平移 1 cm |
| Q / E | 目标绕世界 z 轴转 5° |
| R | 目标复位到末端当前位姿（卡住时用） |

**停下来后能收敛到 0**（实测位置误差 0.000000 mm、`|qvel|` 恰好 0，查看器日志残差连续
25 秒恒为 0.0000）；**跟踪运动目标时误差约 1~3 mm**，稳定不发散。卡在大幅跳变上时
（雅可比伺服法固有的局部极小，目标跳太远会落到别的构型分支）按 R 拉回来再拖。

### 这里踩的坑最多，都别再走一遍

1. **MuJoCo 的四元数顺序是 `(w, x, y, z)`**，Isaac Gym 是 `(x, y, z, w)`。按后者写的话
   姿态误差会恒定卡在 178°（伺服一直往反方向推）。最坑的是「从真解出发误差为 0」这类
   自检**能通过** —— 因为 `q·conj(q)` 在任何自洽约定下都是单位元，和顺序无关。
2. **指令角必须累加，不能每帧从实际关节角重算。** 位置伺服在重力下要靠
   `kp·(ctrl−qpos)=重力力矩` 撑住，实测 `|ctrl−qpos|` 恒为 0.03 rad。纯比例环消不掉
   这个偏差，末端会稳定停在离目标 8 cm 处。累加相当于加了积分作用，才能到厘米级。
3. **但要加抗积分饱和**（`IK_LEAD`）。500 Hz 下指令会越积越远（实测 `|ctrl−qpos|`
   涨到 3.96 rad），机械臂跟不上就彻底失控。
4. **不要写成「迭代到收敛的 IK 求解器」。** 两种都试过且都失败：纯 DLS 单步增量太大
   会震荡（Joint1 一步从 0 跳到 0.9、Joint5 顶到限位）；加回溯线搜索又容易找不到下降
   方向提前卡住（位置误差反而涨到 377 mm）。摊成每帧一小步最稳。
5. **不要用「远距离大增益 / 近距离小增益」的双档切换。** 阈值处 10 倍的增益突变会形成
   极限环，实测手臂一路发散出去。固定 `IK_STEP = 0.001` 最稳（扫过 0.0005~0.010）。
6. **外环必须带 D 项（`IK_KD`），纯积分器必然极限环。** 上面第 2 条要求「指令角累加」，
   累加就是纯积分；纯积分器驱动带滞后的被控对象，**永远收敛不到 0，会一直晃**。实测
   手臂停下来后以 **0.58 Hz 前后摇**，36 秒后位置误差仍有 1.44 mm、`|qvel|` 0.10 rad/s，
   屏幕上看着就是「静止时还在抖」。加任务空间阻尼项就好：

   ```python
   dq = J.T @ np.linalg.solve(J @ J.T + IK_LAMBDA**2 * np.eye(6),
                              err - IK_KD * (J @ qvel))
   ```

   `J·qvel` 是任务空间速度，`IK_KD` 量纲是秒，乘完和 `err` 的 (m, rad) 可直接相减。
   **别写成 `IK_KD * qvel`** —— 少了雅可比和量纲换算，实测把手臂推飞 400 mm。
   `IK_KD = 0.05` 时收敛到 0.000000 mm、`|qvel|` 恰好 0，且最终关节角与不加 D 项的
   解几乎相同（不是卡死，是同一个位形上真停住了）。扫过 0.02~0.5 静止时全部收敛。
7. **这个抖和 `build_model.py` 那边的 250 Hz 数值颤振是两回事**，症状很像但成因不同：
   那个在**腕部姿态**（J6 摆 8.8°，位置指标看不出来），这个在**整条臂**的低频摇晃。
   两个都修好之后才真正静止（查看器日志残差连续 25 秒恒为 0.0000、抓屏 60 帧像素完全相同）。

### 怎么测「停下来还在抖」这种问题

从查看器的 1 Hz 残差打印里看不出来（那只是个 6 维范数，且和姿态混在一起）。有效的做法是
**抓屏连拍 + 帧间差分**：xwd 抓整屏、裁 3D 视口、算相邻帧差分和灰度重心的频谱。
`xwd` 约 4 fps（Nyquist ≈ 2 Hz），够看 0.58 Hz 这种低频摇晃。注意 `xwd` 的
`bits_per_pixel` 字段是色彩深度（24），实际存储按 X 的 bitmap_pad 补齐到 **4 字节/像素**，
要按 `bytes_per_line / width` 算步长，别信那个字段。

## build_model.py 做了什么

转换不是手写 XML，而是让 MuJoCo 自己转，再在结果上补东西：

1. 复制 `../URDF_arm/meshes/` 到 `assets/meshes/`，**面片数超过 20 万的 STL 转成 OBJ**
   （见下面的坑）。
2. 生成 `assets/URDF_arm.urdf`，把 `package://` 路径改写成相对路径 —— MuJoCo 和
   Isaac Gym 一样不认 `package://` 前缀。
3. 用 `mujoco.MjModel.from_xml_path()` 编译这份 URDF，再用 `mujoco.mj_saveLastXML()`
   把编译结果导出成 MJCF。惯性张量、关节坐标系、主轴分解出的四元数这些都交给 MuJoCo
   自己算，比手写可靠。
4. 在导出的骨架上补：`<compiler meshdir>`、地面、天空盒和棋盘格（配色沿用
   `ball/sphere.xml`）、太阳光和环境光、位置伺服执行器、零位 keyframe、相机。
5. 自检：把生成的文件重新编译一遍，编译不过就直接报错。

`--collision` 控制碰撞体：

| 取值 | 说明 |
| --- | --- |
| `none`（默认） | 机械臂的几何体只做可视化（`contype=0 conaffinity=0`），不参与碰撞 |
| `mesh` | 用原始网格做碰撞体 |

## 踩过的坑

- **MuJoCo 的 STL 解码器有 20 万面片硬上限**，`Link3.STL` 有 228234 个面片，直接报
  `number of faces should be between 1 and 200000`。所以超限的网格转成 OBJ 加载。
- **CAD 网格在关节处是互相穿插的。** 用原始网格做碰撞体时，零位就有 6 处穿透接触
  （最深 2.5 cm），静置两秒后关节会被接触力顶到限位，姿态完全不可信。所以默认关掉
  碰撞 —— 这和 Isaac Gym 那边是同一个问题。
- **末端关节的伺服会抖 —— 加重 armature 只解决了一半。** Link6 绕关节的惯量只有
  1.2e-4 kg·m²，`kp=100` 配上 `dt=0.002` 正好卡在显式积分的稳定边界外，实测关节最大
  速度 29 rad/s 持续抖动。给每个关节加上 `armature="0.01"`（电机转子折合到关节上的
  惯量）后大幅缓解。URDF 里没有电枢这个概念，但这是 MuJoCo 机器人模型的标准做法。

  **但它没把边界抬够。** 半隐式欧拉下阻尼项的稳定条件是 `dt < 2·M_ii/kv`，`M_ii` 取自
  `mj_fullM` 对角（注意不是机械臂自身的惯量，是**该关节处**的有效惯量）：
  加 armature 前是 `2×1.2e-4/50 = 4.8e-6 s`，加完变成 `2×0.01/50 = 4e-4 s` —— 涨了
  80 倍，可 `dt=2e-3` 仍超界 4~5 倍：

  ```
  J1  M_ii=0.14221  kv=50 → 需 dt<5.688ms   安全
  J2  M_ii=0.23317  kv=50 → 需 dt<9.327ms   安全
  J3  M_ii=0.16563  kv=50 → 需 dt<6.625ms   安全
  J4  M_ii=0.01157  kv=50 → 需 dt<0.463ms   实际 2ms ← 超 4×
  J5  M_ii=0.01355  kv=50 → 需 dt<0.542ms               超 4×
  J6  M_ii=0.01012  kv=50 → 需 dt<0.405ms               超 5×
  ```

  于是 J4/J5/J6 以 **250 Hz（正好 Nyquist）持续颤振**，`|qvel|` 0.30~0.42 rad/s、永不衰减，
  J6 摆幅 0.154 rad（8.8°）；上表也解释了为什么 J1~J3 一直没事。修法是给 `<option>` 加
  **`integrator="implicitfast"`**，让 MuJoCo 对阻尼项隐式求解：J6 摆幅降到 4.8e-4 rad、
  腕部姿态抖动 4.18° → 0.53°。`build_model.py` 里那段 kv 注释只推了阻尼比
  `ζ = kv/(2√(kp·I))`（那条对 J1~J3 是对的），漏了这条离散稳定边界。

  **最容易漏判的一点：这个抖表现在腕部「姿态」上，不在末端「位置」上。** 末端 `ee_site`
  就挂在 `Link6` 的原点、正在 J6 转轴上，J6 转多少它都不动，所以位置类指标只有 1~3 mm
  看着挺好。要么量姿态误差，要么看腕部转角。
- **geom 上的 `rgba` 优先级高于 `material`**，两边都写的话材质等于白写。所以连杆颜色
  就直接沿用 URDF 里的 rgba，没有另建材质。
- **`mujoco.viewer` 第一次 `sync()` 会做自动取景**，把之前设的相机参数盖掉。要自定义
  初始视角，得等第一次 `sync()` 之后再设。
- `base_link` 被 MuJoCo 并进了 `worldbody`（URDF 的根连杆没有关节），它的质量不参与
  动力学。对固定基座的机械臂没影响，但别拿 `model.body_mass.sum()` 当整机质量 ——
  会少掉 base_link 的 0.3178 kg（所以上面打印的是 4.3055 kg，不是 4.6233 kg）。

## 和 arm_isaacgym 的关系

同一份 URDF 的两个仿真后端，各自独立：`arm_isaacgym/` 走 Isaac Gym（`legged_gym`
环境），`arm_mujoco/` 走 MuJoCo（base 环境）。两边都不认 `package://` 网格路径，
都栽在 CAD 网格自碰撞上。
