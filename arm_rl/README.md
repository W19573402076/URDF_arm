# 机械臂末端 6D 位姿到达的强化学习训练

用 PPO 训练 `URDF_arm` 六轴机械臂，让末端（Link6 坐标系）到达随机指定的
**6D 位姿**（位置 + 姿态）。

```
arm_rl/
├── arm_reach_config.py   # 任务配置（ArmReachCfg / ArmReachCfgPPO）
├── arm_reach_env.py      # 环境（ArmReach，继承 legged_gym 的 LeggedRobot）
├── train.py              # 训练入口
├── play.py               # 加载策略评估精度
├── logs/                 # TensorBoard + model_*.pt
└── logs_train.txt        # 最近一次训练的 stdout
```

机器人资产复用 `../arm_isaacgym/assets/`（与查看器同一份，不重复拷贝 35 MB 网格）。

## 环境与运行

跑在 **legged_gym conda 环境**（Python 3.8，装着 isaacgym 1.0rc4 + rsl_rl 1.0.2 +
torch 2.0.1+cu117）。**必须先 `conda activate`** —— `gymtorch` 需要 JIT 编译，要 `ninja`
在 PATH 上，而 ninja 只在环境的 bin 里：

```bash
conda activate legged_gym
cd /home/wck/mujocoproject/URDF/arm_rl

python train.py --headless                      # 训练，默认 4096 环境 2000 迭代
python train.py --headless --num_envs 1024      # 显存不够就减环境数
python play.py --episodes 200                   # 评估最新 checkpoint
python play.py --num_envs 16                    # 不加 --headless 会开窗口看策略跑
tensorboard --logdir logs/                      # 看曲线
```

训练日志在 `logs/<时间戳>_/` 下：`model_*.pt` 每 100 次迭代存一次，
`events.out.tfevents.*` 给 TensorBoard。

## 任务设计

| 项 | 值 |
| --- | --- |
| 末端参考点 | Link6 坐标系原点（源 URDF 无工具尖） |
| 动作 | 6 维关节位置增量，`target_q = default + 0.25 * action`，PD 转力矩 |
| 时基 | 120 Hz 物理、30 Hz 控制（decimation=4）、episode 5 s = 150 控制步 |
| 终止 | 只按超时；不在到达时提前终止，让策略学会保持住 |
| 目标采样 | 随机关节角 → 正解算末端位姿（保证 100% 可达） |

**观测（30 维）**：关节角偏差 6 + 关节角速度 6 + 末端位置误差 3 +
相对旋转的 6D 表示 6 + 末端位置 3 + 上一帧动作 6。
用 6D 旋转表示（旋转矩阵前两列）而不是四元数或欧拉角，避免 ±q 双重覆盖和万向锁。

**奖励**（基类会把 scale 自动乘以 dt=1/30，所以数值是「每秒」量级）：

| 项 | 形式 | scale |
| --- | --- | --- |
| `tracking_eef_pos` | `exp(-‖Δp‖²/0.3²)` | +2.0 |
| `eef_pos_lin` | `-‖Δp‖` | −0.5 |
| `tracking_eef_ori` | `exp(-θ²/1.0²)`，θ 是相对旋转角 | +1.0 |
| `action_rate` | `-‖a_t − a_{t−1}‖²` | −0.01 |
| `dof_vel` / `torques` | `-‖·‖²` | −0.001 / −1e-4 |
| `dof_pos_limits` | 越界惩罚 | −2.0 |
| `success` | 位姿达标的一次性奖励 | +5.0 |

达标阈值：位置 < 20 mm **且** 姿态 < 0.1 rad（≈5.7°）。

### 有效的改动只有三处

| 改动 | 严格成功率 | 位置中位数 | 姿态中位数 |
| --- | --- | --- | --- |
| v6 基线（256/128/64，2000 迭代） | 7.8% | 72.4 mm | 3.88° |
| → v7 加性奖励改**联合精核** | 9.5% | 51.9 mm | 7.35° |
| → v8 网络改 **512/256/128** | 19.2% | 39.3 mm | 5.68° |
| → v9 训练 2000 → **4000 迭代** | 48.2% | 19.5 mm | 2.67° |
| → v10 续训到 **8000 迭代** | 73.8% | 12.7 mm | 1.56° |
| → v11 续训到 **12000 迭代** | 82.8% | 9.9 mm | 1.27° |
| → v12 续训到 **16000 迭代** | 89.2% | 8.6 mm | 1.09° |
| → v13 续训到 **20000 迭代** | **90.5%** | **7.6 mm** | **0.99°** |

**计划里的验收标准三项全部达成**（成功率 > 90%、位置中位数 < 10 mm、姿态中位数 < 3°）。

收益在递减（16000→20000 只涨 1.3 个点），已经接近收敛。

- **联合精核**（v7）：堵住了「牺牲一项换另一项」的路，位置大幅改善但姿态变差 ——
  只是把预算重新分配了。
- **加大网络**（v8）：**第一次位置和姿态同时改善，成功率翻倍**。说明「两项同时精确」
  要求策略拟合更精确的逆动力学，[256,128,64] 的表达力不够。这解释了为什么之前调奖励、
  调 kp、加重力补偿都只在 7~10% 附近晃。
- **延长训练**（v9 / v10）：效果最大，两次各把成功率翻 2.5 倍和 1.5 倍。2000 迭代时
  曲线远未收敛。

**结论：之前的瓶颈一直是「算力 + 容量」，不是算法或奖励设计。** 七次在奖励和控制器上
的折腾加起来只把成功率从 7.7% 抬到 9.5%，而把网络放大一倍、训练轮数翻两番，到了 73.8%。

**距离计划里的验收标准**（成功率 > 90%、位置中位数 < 10 mm、姿态中位数 < 3°）：
姿态中位数 1.56° 已达标，位置中位数 12.7 mm 接近，成功率 73.8% 还有差距。
8000 迭代时曲线仍未完全收敛，继续续训应该还能涨。

三次关键改动都严格做了单变量对比（v7 只改奖励、v8 只改网络、v9/v10 只改迭代数）。

**续训**：rsl_rl 的 `load()` 会恢复 `current_learning_iteration`，所以可以接着练：
`python train.py --headless --resume --max_iterations 4000`（从上次的 checkpoint 再跑 4000 次）。

### 关键发现：成功率和干预手段基本无关

六次训练里我换了 PD 增益、奖励核形状、奖励权重、加了前馈重力补偿 —— **成功率始终
没离开 7~8%**。但位置和姿态的中位数在剧烈互换：

- v4（位置权重占优）拿到最好的位置 26.0 mm，姿态 14.46°
- v5/v6（权重持平）拿到最好的姿态 3.88~4.65°，位置却退到 62~72 mm

**策略在一条帕累托前沿上滑动，而不是被推进前沿之外。** 调权重只是把误差从一头挪到
另一头，动不了「两项同时满足」的概率。

重力补偿是这里面最值得说的：它本身**完全正确**（见下节验证），消掉了 PD 在重力下
0.19 rad 的稳态下沉，但成功率纹丝不动。这说明**瓶颈不在动力学，在奖励结构**。

### 下一步该改的是奖励，不是动力学

根本问题在于奖励是**加性**的：`w_pos·r_pos + w_ori·r_ori`，策略优化的是加权和，
不是「两项同时满足」。达标判据却是逻辑与。这两件事不一样，而且当两项互相冲突时，
加性和的最优解**必然**是各让一步 —— 这正是观察到的现象。

应该改成直接表达「同时满足」的形式，例如：

- 乘性核：`r = exp(-(err_pos/σ_p)² - (err_ori/σ_o)²)`，只有两项都小才给高奖励
- 或者取两者较小值：`r = min(r_pos, r_ori)`
- 或者大幅提高 `success` 的权重，让它主导

这是性价比最高的一步，还没试过。

## 踩过的坑

按踩到的顺序：

1. **导入顺序**。必须先 `import isaacgym` 再 `import torch`，否则报
   `PyTorch was imported before isaacgym modules`。而且 `legged_gym.envs` 和
   `legged_gym.utils.task_registry` 之间有循环导入，只有先从 `legged_gym.envs` 进才不炸。
   `train.py` / `play.py` 的导入顺序是照抄 `legged_gym/scripts/train.py` 的，别重排。

2. **`gymtorch` 要 JIT 编译**，需要 `ninja`。不激活 conda 环境直接跑，
   会报 `RuntimeError: Ninja is required to load C++ extensions`。

3. **目标位置必须换算到基座系**。刚体状态张量给的是世界坐标，含各 env 的网格偏移
   （`env_spacing` 决定），实测 x 一直跑到 30 m。距离校验用世界坐标的话几乎所有目标
   都被判不合格，最后只能取兜底的"最优"目标，训练完全跑偏。要用
   `ee_pos - env_origins`。

4. **奖励核的参数必须匹配实际误差尺度**。复位后立即的位置误差 mean 0.447 m、
   姿态误差 mean 2.20 rad。最初按直觉取的 σ_pos=0.1、σ_ori=0.3 让奖励核平均值只有
   0.0019 / 0.0015 —— 等于没有梯度信号，训练不动。改成 0.3 / 1.0 后平均奖励核
   升到 0.207 / 0.047。

5. **平方指数核在近目标处梯度为 0**，精度区间信号很弱（误差 0.02 m 和 0.1 m 的奖励
   只差 10%）。所以额外加了线性项 `-‖Δp‖`，梯度恒定，负责把末端往目标拉。

6. **`soft_dof_pos_limit` 不能收窄**。Joint3 的零位 0.35 正好是它的行程下限，
   若把软限位设成行程的 95%（下限变 0.411），机械臂**静止时就在惩罚区里**，
   实测 13% 的关节位置持续被扣分。必须给 1.0，只在真正越界时惩罚。

7. **`_reset_dofs` 要重写**。基类实现是 `default_dof_pos * rand(0.5, 1.5)`，
   Joint3 的零位 0.35 乘 0.5 就掉到行程外面去了。改成在零位附近加小扰动再夹到行程内。

8. **`_get_noise_scale_vec` 要重写**。基类实现里有针对腿足观测结构的硬编码切片，
   其中 `[24:36]` 会越过本任务 30 维观测的边界静默截断。本任务默认关噪声，
   要开就得按新结构重写尺度。

9. **`_post_physics_step_callback` 要重写**。基类会按 `commands.resampling_time`
   周期性重采指令 —— 到达任务要的是 episode 开始时定目标之后不变，否则任务变成跟踪。

10. **自碰撞要关**。七个连杆的 CAD 网格在关节处互相穿插（MuJoCo 侧实测零位就有 6 处
    穿透接触，最深 2.5 cm）。`asset.self_collisions = 1` 会传给
    `gym.create_actor(..., collision_filter=...)`，让同一个 actor 内的形状互不碰撞。

## 前馈重力补偿（已实现，验证通过）

`arm_reach_env.py` 的 `_compute_torques` 里加了 `τ_g = -Σ_i J_com_i^T · (m_i · g)`。

验证方式：零动作命令（PD 目标 = 零位），跑 300 控制步后测稳态误差 ——
**六个关节全部为 0.00000 rad**，速度峰值 5e-6 rad/s，PD 力矩与前馈力矩逐位相同，
说明前馈精确承担了全部重力载荷。对比：没有补偿时 Joint2 在 kp=80 下有约 0.19 rad
的稳态下沉。

公式的正确性用 MuJoCo 的 `qfrc_bias`（零速度时即重力力矩）逐点对比过，200 组随机
姿态下数值完全吻合。

**关掉方式**：注释掉 `_post_physics_step_callback` 里的 `self._update_gravity_ff()`
和 `_compute_torques` 的覆写即可。

### 踩过的坑（这里花了最多时间）

1. **Isaac Gym 的 Jacobian 语义要靠有限差分测**，别猜。实测结论：
   - 世界系，不是体坐标系
   - 参考点在刚体**质心**，不是刚体原点（用 `原点雅可比 - skew(R·com) @ 角雅可比`
     验证，20 个非零项里命中 19 个）
   - 刚体维度是 `num_bodies - 1`：`base_link` 是固定基座被并掉了，
     `jacobian[:, i]` 对应 `Link(i+1)`，所以质量数组要从 `props[1:]` 取
   - 最后一维就是关节数，没有额外的 base 列
2. **刷新时机**。`refresh_jacobian_tensors` 必须在读完关节角之后调用。我第一次验证
   时跑完 400 步稳态却忘了刷新，用的还是复位时的旧 Jacobian，白折腾一轮。
3. **别拿 `kp*(q_cmd - q_eq)` 当重力力矩的基准**。关节碰到限位时那个式子不成立
   （限位约束会补上差额），实测能算出 41 N·m 这种超过力矩上限的值。
   干净的做法是拿另一个仿真器（MuJoCo）的 `qfrc_bias` 做逐点基准。
4. **符号**。`Σ J^T·(m·g)` 算出来的和保持力矩差一个负号。我第一次对比时"平均绝对
   误差 14.53 N·m"正好是两倍幅值，就是这个负号造成的。

## 给末端下指令（command_pose.py）

用训好的策略把末端开到指定位姿，窗口里实时看：

```bash
python command_pose.py --preset 1                      # 用预设目标
python command_pose.py --random                        # 随机目标（训练分布）
python command_pose.py --pos 0.0 0.40 0.30 --euler -130 2 -63    # 位置 + 欧拉角(度)
python command_pose.py --pos 0.0 0.40 0.30 --quat -0.365 0.768 -0.483 0.207   # 位置 + 四元数
```

窗口里按 `1~5` 切预设、`R`/空格 换随机目标、`V` 暂停刷新、`ESC` 退出。目标处会画出
红色线框球 + 三色坐标轴（红=x 绿=y 蓝=z，轴朝向就是目标姿态）。终端每 0.5 秒打印
一次末端误差。

**运行时可以直接在终端里输入新目标**（回车生效，和切预设一样会重置 episode）：

```
pos 0.1 0.35 0.30                 只改位置 [m]
euler -100 0 180                  只改姿态，欧拉角 [度]
quat -0.02 0 -0.766 0.643         只改姿态，四元数 (w x y z)
pos 0.05 0.4 0.35 euler -120 5 170   一起改，关键词顺序随意、可任意组合
random                            随机目标（训练分布）
preset 3                          用预设 3
help / quit
```

只改一项时另一项保持当前目标的值。启动时脚本会打印**零位末端的位姿**，可以直接拿那行
改数字当起点。

实现上是用后台线程读 stdin + 主循环里非阻塞取队列 —— 直接用 `input()` 会把仿真的
主循环卡住。窗口键盘按键走的是 Isaac Gym 的 viewer 事件，和终端输入互不影响。

**中文输入法的坑**：输入法会截获字母键（按 `R` 弹候选框，按键根本送不到窗口）。脚本
开头设了 4 个环境变量禁用输入法，另外空格也绑了同一个功能做兜底。做法抄自
`../ball/simulate.py`。

位置是**基座坐标系**下的（基座在原点），和训练时目标的表达方式一致。

### 实测：策略对不同目标的表现差别很大

| 目标来源 | 位置误差 |
| --- | --- |
| 随机构型 r2 | 43 mm / 5.6° |
| 随机构型 r1 | 79 mm / 14.0° |
| 预设 1 正前方-中 | 217 mm / 16.9° |
| 预设 3 左侧 | 387 mm / 3.6° |
| 随机构型 r4 | 243 mm / 23.8° |

这和 400 个随机目标的评测分布吻合：位置误差中位数 70 mm、**均值 110 mm、p95 363 mm**，
同时满足 20 mm 和 5.7° 的只有 6%。**有的目标能到 4 cm 出头，有的会停在 30 cm 开外。**

所以这个脚本不只是"能用"的演示，它同时是最直接的策略能力检验 —— 结论是：策略学到了
粗定位（厘米到分米级），但离"精确到位"还差得远。原因见上面「关键发现」一节。

`--random` 模式走的是环境自己的采样器（随机关节角正解），和训练时的目标分布完全一致，
比手挑的预设更能反映真实水平。

## 试过但没用的方向（别再走一遍）

**调大 kp。** kp=400/100 训练了两次，都明显更差（1.3% / 1.0% vs 80/20 的 7.7%）。
原因是力矩上限只有 URDF 给的 20 N·m，kp=400 时位置超前 0.05 rad 就吃满力矩，
动作空间长期饱和，策略失去力矩的精细调节能力。

**奖励核退火。** 把 σ_pos 随训练从 0.3 收到 0.08，成功率从 7.7% 掉到 1.3%。
核收窄到 0.08 后误差 0.3 m 处的奖励是 exp(-14) ≈ 1e-6，绝大多数状态奖励都是 0，
PPO 的价值函数学不动。**正确做法是粗核 + 精核叠加**，而不是把粗核收窄。

**前馈重力补偿。** 实现正确、验证通过（见上节），但成功率没有变化（8.2% → 7.8%）。
它消掉了动力学上的稳态误差，却动不了成功率 —— 这本身就是"瓶颈在奖励结构"的证据。

## 还没试的方向

**1. 继续加容量 / 延长训练。** v8 证明容量是真瓶颈，而且训练曲线末尾还在上升。
可以再翻一档网络（[1024, 512, 256]）、或者把迭代数提到 3000~4000（已在跑 4000）。
这是目前唯一被验证有效的方向。

**2. 提高控制频率。** 现在是 30 Hz 位置增量 + PD。提到 50~60 Hz 能减小每个控制步的
跟踪滞后，对精度有直接好处。

**3. 放宽验收标准（零成本）。** 如果 50 mm / 11.5° 或 100 mm / 22.9° 够用，
v8 已经相当可用（55.0% / 85.5%）。改 `arm_reach_config.ArmReachCfg.rewards` 里的
`success_pos_tol` / `success_ori_tol` 即可，不用重训。

**4. 换动作接口。** 现在动作是关节位置增量、经 PD 转力矩。可以试直接给关节力矩
（`control_type='T'`）配合前馈补偿，让策略对力矩有更细的控制。

**5. 课程学习：先位置后姿态、由近及远。** 先只要求位置、目标放在容易够到的地方，
达标后再加姿态要求和难度。这类任务用课程通常比一步到位稳得多。

**3. 换更高精度的控制接口。** 现在是 30 Hz 位置增量 + PD。可以试 30→50 Hz 控制频率、
或把动作改成直接给关节力矩（`control_type='T'`）配合前馈补偿。

**4. 加大网络 / 延长训练。** 当前 `actor_hidden_dims = [256, 128, 64]`（从 legged_gym
默认的 [512,256,128] 调小了）。逆动力学的映射可能需要更大容量。这条优先级最低，
因为成功率六次都没动过，不像是容量问题。

## 架构说明：为什么代码不放进 legged_gym

legged_gym 的官方做法是把任务写进 `legged_gym/envs/<robot>/` 并在
`legged_gym/envs/__init__.py` 里注册。但 `/home/wck/Gym/legged_gym-master` 是第三方
clone 且**不是 git 仓库**，往里塞代码既不受版本控制、重装就丢。

所以这里改成：env 类**继承 `LeggedRobot`** 拿到全部现成机制（sim 搭建、张量 API 接线、
PD 力矩控制、reset 骨架、按 `_reward_<名字>` 约定自动注册奖励、TensorBoard 集成），
然后从自己的模块调用 `task_registry.register(...)` —— 那是个全局单例，可以从任意位置注册。
训练和评估走 `task_registry.make_env` / `make_alg_runner`，`log_root` 指到本目录的 `logs/`。
**legged_gym 一行都没改。**
